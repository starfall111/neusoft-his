# db/migrations · 数据库增量迁移脚本（V2.4 起生效）

> 规则来源：组长 2026-09-10 决策，已写入根目录 AGENTS.md **铁律一**与《项目拆解设计说明书》6.3。**自 V2.4 起，一切数据库结构变更（表/字段的加入与删除、类型、索引、约束及随之的种子调整）一律通过本目录的独立 SQL 脚本交付，禁止再直接修改 `db/init.sql`。**

## 目录约定

| 项 | 约定 |
| --- | --- |
| 基线 | `db/init.sql` 定格为 **V2.4 全量基线**（六表 + 种子 + patient_user.status）；仅当 B 里程碑合并时可在其头部追加「已应用迁移清单」注释，不改表结构 |
| 脚本命名 | `V{版本号}__{英文短描述}.sql`，版本号与契约版本联动递增（如 V2.4 之后是 V2.5），**不复用、不跳号**；两个下划线分隔 |
| 执行顺序 | 全新环境：先 `init.sql` 建库 → 再按版本号**升序**逐个执行本目录脚本；已有环境：只执行未应用的脚本 |
| 唯一维护人 | **后端 B**（与 init.sql 同一责任人）；发起对齐走 AGENTS.md 铁律一 |
| 脚本头部注释 | 必含：版本号、日期、作者、关联契约（dto-contract / mock-data / 拆解说明书版本与章节）、适用环境（增量升级 or 全新建库可跳过） |
| 正向 + 回滚 | 每个脚本正文为正向语句（ALTER/CREATE/INSERT…），文末以注释形式附**回滚语句**，便于演示环境回退 |
| 已应用脚本 | **禁止修改与删除**（含已提交未应用的，改动走新脚本修正）——保证任何环境按序重放结果一致 |

## 脚本模板

```sql
-- ============================================================
-- 迁移脚本 · V{版本}  {一句话标题}
-- 日期：YYYY-MM-DD    作者：B
-- 关联：dto-contract Vx.x / mock-data Vx.x / 拆解文档 Vx.x（章节）
-- 适用：已按 init.sql Vx.x 建库的环境增量升级；全新环境执行 init.sql 可跳过
-- ============================================================

-- 正向：
-- ALTER / CREATE / INSERT ...

-- 回滚（如需回退，取消注释执行）：
-- ...
```
